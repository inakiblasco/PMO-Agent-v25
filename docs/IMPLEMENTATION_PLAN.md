# PMO Agent 今後の実装計画

更新日: 2026-10-09。現在の証拠・状態は [実装状況](IMPLEMENTATION_STATUS.md)、責務と境界は [基本設計](PMO_AGENT_DESIGN.md)。本書はこれからの作業と完了条件の正本。

## 優先順位

| 順序 | 作業 | 完了条件 |
| --- | --- | --- |
| 1 | WorkIQ の実データ照合 | 既知の関連メール・Teams 会話がある ADO タスクで検索し、回答・リンク・日時を照合する |
| 2 | 同意・会話継続・Harness 安定化 | 同意前→同意→同じ会話で再検索を記録。未完了 call の400と mode 切替引数エラーが再発しない |
| 3 | 利用者別認証・権限の検証 | 未同意・別ユーザー・権限不足で意図した同意と参照範囲を確認する |
| 4 | ADO / WorkIQ 初期実装の証拠整理・統合 | WorkIQ の初期完了を判断。ADO の操作別 ID / revision / trace、WorkIQ の検索結果を記録し機能ブランチを統合する |
| 5 | Cosmos DB による業務状態・監査の永続化 | 再起動、同時実行、複数インスタンスで復元・claim・成否照合が機能する |
| 6 | 実メッセージ送信 | 送信経路と認証を選び、宛先照合・永続重複防止・頻度制限・監査を検証する |
| 7 | 出典・検索・エラー処理の改善 | 実出典を構造化し、検索キー・設定上限・原因分類を実契約に沿って改善する |
| 8 | 監視・配備再現性・公開チャネル | 機密情報を抑制した相関ログ、RBAC/IaC、Teams 等の意図した利用経路を検証する |

5以降は詳細設計・検証結果によって順序を調整する。現在は利用者が承認する対話操作を対象とし、無人実行の完了保証は対象外。

## 直近の検証手順

1. 検証に使う ADO タスクと、対応する Microsoft 365 の既知情報を決める。
2. 未同意状態が必要なら、未同意の検証ユーザーかユーザー単位の解除方法を確認する。共有 Connection / Toolbox は削除しない。
3. Playground の対象 version と新規会話を確認して検索する。Harness の計画承認と WorkIQ OAuth 同意を区別する。
4. 同意要求、同意待ちの tool output、停止応答を確認する。
5. 同意後、同じ会話で再依頼し、回答・参照リンクを実データに照合する。再検索と別タスクでも履歴400がないことを確認する。
6. ID、version、trace、結果区分、確認事項を記録する。本文・同意URL・トークンは記録しない。

WorkIQ 初期実装の完了は、Hosted の実取得と内容照合、同意・再開の確認、ADO 承認境界の維持をもって判断する。接続だけで検索の正確性を完了としない。

## Cosmos DB 実装の具体化

- Proposal / Audit / MessageDelivery の永続Storeを Protocol の背後に配置する。mock はテスト用に残す。
- session / 利用者・tenant の所有権、partition、保存期間、削除方法、RBAC を定義する。
- ETag 等を使う原子的 claim と状態遷移を実装し、同じ Proposal の並行適用を防ぐ。
- applying のまま再起動した記録を復元し、ADOとの照合が必要な成否不明として扱う。自動再送しない。
- 記憶用途の回答保存は承認・監査と分け、出典とアクセス制御を設計する。
- 既存 private endpoint / DNS と Hosted VNet からの到達、再起動、障害注入、複数インスタンスを検証する。

## 実送信・公開の具体化

MessageClient の候補は Microsoft 365 の専用 API / Gateway、または Autopilot 等。採用前に委任・アプリ認証、ライセンス、宛先、送信・監査の契約を確認する。固定プロンプトだけを送信認可境界にしない。

Teams 公開と無人の定期観測は別の計画。前者は利用者認証・Activity channel・配布範囲、後者はユーザー不在時の WorkIQ / ADO 認証対応と耐久実行を検証する。

## 運用・品質の継続課題

- ADO 作成・更新・History コメントの操作別実検証、同時編集、dispatch 後通信失敗の成否照合。
- WorkIQAgent.Ask の操作権限とサービス側読み取り専用制約の確認。
- WorkIQ 合成回答と検証済み出典の分離。MCP 直接接続は必要性と実仕様を調べてから判断。
- SDK 更新時の OAuth Content・call 終端・Host 応答互換性の確認。
- 外部本文・認証情報を漏らさないログと、エラー種別・性能・接続往復コストの監視。
